# Фикс безопасности: доступ к чатам только для участников или админов

## Проблема
При вставке прямой ссылки `/chat/:id` любой авторизованный пользователь мог увидеть содержимое чужого чата, если знал его ID. Не было проверки на членство в чате.

## Решение
Добавлена проверка глобальной роли `isAdmin` в трёх критичных GET-эндпоинтах:

### 1. **GET /api/chats/:id** (строка 3895)
**До:**
```js
const isMember = db.chatMembers.find(m => m.chatId === req.params.id && m.userId === req.userId);
if (!isMember) return res.status(403).json({ message: 'Нет доступа' });
```

**После:**
```js
const isMember = db.chatMembers.find(m => m.chatId === req.params.id && m.userId === req.userId);
const currentUser = db.users.find(u => u.id === req.userId);
const isAdmin = currentUser?.isAdmin === true;

// Доступ только участникам чата или глобальным админам
if (!isMember && !isAdmin) {
  return res.status(403).json({ message: 'Нет доступа' });
}
```

### 2. **GET /api/messages/:chatId** (строка 4509)
Аналогичная проверка: доступ только участникам чата или глобальным админам.

### 3. **GET /api/messages/:chatId/comments/:postId** (строка 4502)
Аналогичная проверка: доступ только участникам чата или глобальным админам.

## Поведение

| Роль                  | Доступ к чужому чату | Доступ к своему чату |
|-----------------------|----------------------|----------------------|
| Обычный пользователь  | ❌ 403 Нет доступа   | ✅ OK                |
| Глобальный админ      | ✅ OK (модерация)    | ✅ OK                |

## Защита от IDOR-атак (Burp Suite / Repeater)

### Сценарий атаки
Злоумышленник перехватывает запрос `GET /api/chats/123` в Burp Suite и подменяет `chatId` на `456`, пытаясь получить доступ к чужому чату.

### Защита
1. **`req.userId` берётся ТОЛЬКО из JWT токена**, а не из параметров запроса:
   ```js
   // authMiddleware (строка 1014-1022)
   const { userId, deviceId } = verifyAccessToken(auth.slice(7));
   req.userId = userId; // Взято из JWT, а не из req.body/query/params
   ```

2. **JWT подписан секретным ключом** (`JWT_SECRET`):
   ```js
   // verifyAccessToken (строка 1000)
   const payload = jwt.verify(token, JWT_SECRET);
   ```
   Злоумышленник **не может** подделать токен без секретного ключа.

3. **`tokenVersion` защищает от использования украденных токенов**:
   ```js
   // verifyAccessToken (строка 1005)
   if (Number(payload.tv || 0) !== tv) throw new Error('token_revoked');
   ```
   После logout пользователя его токены становятся недействительными.

4. **Проверка членства в чате блокирует доступ**:
   ```js
   // GET /api/chats/:id (строка 3896-3902)
   const isMember = db.chatMembers.find(m => m.chatId === req.params.id && m.userId === req.userId);
   if (!isMember && !isAdmin) return res.status(403).json({ message: 'Нет доступа' });
   ```

### Что НЕ может сделать злоумышленник

| Атака                                      | Результат                          |
|--------------------------------------------|------------------------------------|
| Подменить `chatId` в URL                  | ❌ 403 Нет доступа (проверка членства) |
| Подменить `userId` в `req.body`           | ❌ Игнорируется (используется JWT) |
| Подделать JWT токен с чужим `userId`      | ❌ 401 Invalid token (подпись не совпадает) |
| Украсть токен и использовать после logout | ❌ 401 Token revoked (tokenVersion не совпадает) |

## Безопасность других эндпоинтов

Проверены и оставлены без изменений (безопасны):

- **POST /api/messages/:chatId** → проверка `isMember` в `handleSendMessage` (строка 4647)
  - Админ НЕ может писать в чужие чаты без членства (правильно)
  - Админ может только читать (модерация)

- **PATCH /api/chats/:id/archive, pin, mute** (строки 3846-3870) → проверка `isMember`
  - Это личные настройки (архив, закрепление, мут) → требуют членство

- **PATCH /api/chats/:id** (строка 4068) → проверка `isMember` + `hasGroupRight`
  - Редактирование групп → требует членство + права админа группы

- **PATCH /api/chats/:id/members/:userId/admin** (строка 3994) → проверка `hasGroupRight`
  - `req.params.userId` — ID целевого участника (безопасно)
  - `req.userId` — текущий пользователь из JWT (безопасно)

- **DELETE /api/chats/:id/leave** (строка 4119) → проверка `isMember`
  - Выход из чата → требует членство

## Рекомендации по безопасности

1. **Никогда не доверяйте параметрам из запроса** (`req.body`, `req.query`, `req.params`) для идентификации пользователя. Используйте только `req.userId` из JWT токена.

2. **JWT должен быть подписан секретным ключом**, который хранится только на сервере (не в коде, а в переменных окружения).

3. **`tokenVersion` обязательна** для защиты от использования украденных токенов после logout.

4. **Проверяйте членство в чате** перед предоставлением доступа к его данным (сообщениям, участникам, метаданным).

5. **Админы имеют доступ к любым чатам** только для чтения (модерация). Они НЕ могут писать сообщения в чужие чаты без членства.
